# 대시보드 페이지 설계 문서

## 배경 및 목적

[2026-08-03-clan-scrim-dashboard-design.md](2026-08-03-clan-scrim-dashboard-design.md)에서 정의한 MVP의 핵심 페이지를 만든다. 방문자가 클랜 내전 결과를 한눈에 볼 수 있는 화면이며, 랜딩페이지의 CTA("대시보드 보기")가 실제로 이동할 곳이다.

이번 설계는 **화면 구성(UI/레이아웃)에 한정**한다. 카카오 PUBG API 연동과 실제 매치 데이터 수집은 별도 스펙 대상이며, 이번 범위에서는 실제 데이터와 동일한 형태의 목업 데이터로 화면을 채운다.

**범위 밖**: 클랜원 개인별 상세 페이지(`/member/[id]`), 관리자 페이지(티어 수동 지정, 다시보기 URL 입력, 내전 CRUD). 이번 스펙은 대시보드 메인 화면만 다룬다.

## 라우트 & 페이지 구성

- 라우트: `/dashboard`
- 로그인 없이 공개 (MVP 스펙의 기존 방침과 동일)
- 기존 `Nav`, `Footer` 컴포넌트를 그대로 재사용한다
- 페이지 순서: 상단 티어 랭킹 → 하단 최근 내전 목록

### 선행 수정: nav/footer의 `ready` 플래그 연결

`siteConfig`의 nav·footer 링크 항목에는 이미 `ready: boolean` 필드가 있지만, 현재 `Nav.tsx`/`Footer.tsx`는 이 값을 읽지 않고 모든 항목을 비활성 처리하고 있다. `/dashboard`가 실제로 생기므로:

- `siteConfig.nav`의 `DASHBOARD` 항목과 `siteConfig.footer.links`의 `대시보드` 항목을 `ready: true`로 바꾼다.
- `Nav.tsx`/`Footer.tsx`가 `ready`를 확인해 `true`면 `next/link`로, `false`면 기존처럼 `aria-disabled` span으로 렌더링하도록 고친다.
- `MEMBERS`/`MATCHES`/`RANKINGS`, `클랜원`/`매치 기록`/`랭킹`은 계속 비활성으로 둔다 (해당 페이지가 아직 없음).

## 데이터

백엔드가 없으므로 실제 데이터 구조와 동일한 형태의 목업을 `lib/dashboardData.ts`에 둔다.

```ts
export interface Member {
  id: string;
  ign: string;
  tier: number; // 0, 1, 1.5, 2, 2.5, 3, 3.5, 4, 4.5
  score: number; // 최근 10경기 기준 종합 점수 (킬점수+순위점수 가중합, 가중치 미확정)
}

export interface ScrimSession {
  id: string;
  title: string; // "2026 RAGE 클랜내전 #10"
  date: string; // ISO date, "2026-08-03"
  participantCount: number; // 보통 64
  matchCount: number; // 보통 4
  replayUrl: string | null; // 관리자가 수동 입력. 없으면 null
}
```

`score`의 가중치는 [2026-08-03 스펙](2026-08-03-clan-scrim-dashboard-design.md)에서 이미 미확정으로 남겨둔 값이다. 이번 스펙에서도 확정하지 않고, 목업 데이터에는 그럴듯한 임의의 점수를 직접 넣는다. 실제 API 연동 시 이 파일의 배열만 실제 계산 결과로 교체하면 되도록, 화면 컴포넌트는 이 두 인터페이스 형태에만 의존하고 계산 로직을 갖지 않는다.

## 티어 랭킹 (상단)

**티어 그룹 탭** (5개, 기본값은 첫 번째):

| 탭 라벨 | 포함 티어 |
|---|---|
| 전체 | 모든 티어 통합 |
| 0~1.5티어 | 0, 1, 1.5 |
| 2~2.5티어 | 2, 2.5 |
| 3~3.5티어 | 3, 3.5 |
| 4~4.5티어 | 4, 4.5 |

`전체`는 티어 구분 없이 클랜 전체를 종합 점수로 통합한 순위다.

**표시 방식**: 선택된 탭의 Top3를 시상대(포디움) 형태로 보여준다 — 1위는 가운데 가장 크게, 2위는 왼쪽, 3위는 오른쪽. 각 카드는 순위 배지, IGN, 종합 점수를 담는다. `전체` 탭에서는 해당 클랜원의 티어 배지를 추가로 보여준다(어느 티어 소속인지 알 수 있어야 하므로). 티어 그룹 탭(`0~1.5티어` 등)에서는 이미 그룹으로 필터링돼 있으므로 티어 배지를 생략한다.

**정렬**: 종합 점수(`score`) 내림차순.

**Top3가 채워지지 않는 경우**: 예를 들어 `4~4.5티어`에 클랜원이 1명뿐이면 2·3위 자리가 빈다. 빈 자리는 카드 자체를 "—"로 표시하고 순위 배지를 흐리게 처리한다. 데이터 없음을 숨기지 않고 그대로 드러낸다.

**동점 처리**: 이번 스펙에서는 규칙을 정하지 않는다. 목업 단계에서는 배열 순서를 그대로 따른다.

## 최근 내전 목록 (하단)

**목록**: 최근 10개, 최신순.

**행 구성** (참고한 PUBG e스포츠 일정 목록 스타일을 내전 규모에 맞게 축소):

| 항목 | 내용 | 비고 |
|---|---|---|
| 내전 이름 | `2026 RAGE 클랜내전 #10` | 연도 + 클랜명 + "클랜내전" + 그 해 몇 번째인지 |
| 날짜/요일 | `2026-08-03 (일)` | |
| 참여 인원수 | `64명` | 보통 64명으로 고정값에 가깝지만 실제 값을 표시 |
| 경기 수 | `4경기` | 보통 4경기 |
| 다시보기 | 버튼 | `replayUrl`이 있으면 새 탭으로 여는 링크 버튼, 없으면 `다시보기 준비중`으로 흐리게 비활성 표시 (헤더 nav 비활성 처리와 같은 톤) |

## 콘텐츠 분리 원칙

랜딩페이지와 동일한 원칙을 따른다. 목업 데이터와 티어 그룹 정의는 `lib/dashboardData.ts` 한 곳에 두고, 컴포넌트는 이를 가져다 쓰기만 한다.

## 향후 확장 (이번 스코프 아님)

- 카카오 PUBG API 연동, 실제 매치 수집·저장
- 클랜원 개인별 상세 페이지 (`/member/[id]`)
- 관리자 페이지: 클랜원 티어 수동 지정, 내전별 다시보기 URL 입력, 내전 세션 관리
- 동점 처리 규칙

## 알려진 미해결 사항

- 종합 점수 가중치가 미확정이다 (2026-08-03 스펙에서 이어지는 리스크).
- 티어 그룹 경계(`0~1.5`, `2~2.5` 등)는 이번 대화에서 정한 초기값이며, 실제 클랜원 분포를 보면서 조정될 수 있다.
