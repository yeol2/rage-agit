# 02 팀 구성 테이블 — 고정(fix) + 드래그 이동으로 전환

## 배경

직전 스펙(2026-08-19 "02 표 스왑 + VIP 정렬")에서 02 표는 "클릭해서 선택 →
같은 티어 칼럼의 다른 칸 클릭 → 스왑"으로 구현·커밋됐다(621cb32). 이번 스펙은
그 인터랙션 모델 자체를 바꾼다 — 클릭의 의미를 "고정(fix) 토글"로 재정의하고,
자리 재배치는 01에서 쓰던 드래그 앤 드롭 방식으로 옮긴다. 고정은 나중에 만들
전체/티어별 리롤이 그 사람을 건드리지 않게 하려는 준비 작업이다.

## 범위

**포함**:
- `scrim_roster_entries.fixed` 컬럼 추가.
- 02 표 네임플레이트 클릭 → 그 사람 하나만 `fixed` 토글(고정/해제).
- 자리 재배치는 드래그 앤 드롭으로 변경(같은 티어 칼럼 안에서만, 기존 스왑 API
  재사용). `fixed`인 사람은 드래그 자체가 안 되고, `fixed`인 사람의 칸에는
  드롭이 막힌다(스왑 불가).
- 4티어 칼럼 오른쪽에 "고정" 칼럼 추가 — 팀 행 단위로 눌러 그 팀 4명 전체를
  고정/해제(일부만 고정돼 있으면 항상 "전부 고정"으로 맞춘 뒤, 다시 누르면
  전부 해제).
- 네임플레이트에 고정 여부를 보여주는 작은 배지.
- 02 표 셀 패딩을 줄여 더 컴팩트하게.

**제외**:
- 전체/티어별 리롤(고정 기능을 실제로 쓸 다음 스펙).
- VIP 정렬 버튼은 그대로 유지(이번 변경과 무관, 드래그 이동 규칙만 따른다 —
  스왑 대상이 `fixed`면 그 자리는 건너뛰지 않고 그냥 못 바꾼다는 제약은
  VIP 정렬에는 적용하지 않는다. VIP 정렬은 서버가 계산한 스왑을 그대로
  적용하는 기존 동작을 유지한다 — `fixed`인 사람을 건드리는 경우는 관리자가
  드래그를 막아뒀으니 웬만해선 안 생기고, 생기더라도 이번 스펙 범위 밖이다).

## 데이터 모델 (`supabase/migrations/0019_scrim_roster_fixed.sql`)

```sql
alter table scrim_roster_entries add column if not exists fixed boolean not null default false;

grant select (fixed) on scrim_roster_entries to anon;
grant select (fixed) on scrim_roster_entries to authenticated;
```

## 인터랙션

- **클릭**: `RosterEntry.fixed`를 반전해 저장(개인 단위). 팀 전체가 아니라
  특정 티어 한 자리만 고정하고 싶을 때 쓴다.
- **드래그 앤 드롭**: 같은 티어 칼럼의 두 칸 사이에서만 가능(01과 같은 제약).
  - 출발점이 `fixed`면 애초에 `draggable=false`라 집을 수 없다.
  - 도착점이 `fixed`면 드롭이 막힌다(그 칸은 그대로 남고 아무 일도 안 일어난다).
  - 성공하면 기존 스왑 API(`POST /api/scrim-roster/entries/swap`)를 그대로
    호출한다 — 이 API 자체는 안 바뀐다.
- **"고정" 칼럼(팀 행 단위)**: 그 팀 4명 중 하나라도 고정 안 돼 있으면 클릭 시
  4명 전부 고정. 4명 다 고정돼 있으면 클릭 시 4명 전부 해제.

## API

### `PATCH /api/scrim-roster/entries/[entryId]` (확장)

기존에는 `{ tierSlot }`만 받았는데, `{ fixed: boolean }`도 받을 수 있게
넓힌다. 둘 중 온 필드만 갱신한다(둘 다 오면 둘 다 갱신 — 이번 스펙에서 동시에
보낼 일은 없지만 막을 이유도 없다).

### `POST /api/scrim-roster/entries/team-fix` (신규)

`{ rosterId: string, teamNumber: number, fixed: boolean }` — 그 roster 안에서
`team_number`가 일치하는 모든 entry의 `fixed`를 지정한 값으로 일괄 저장한다.
목표 값(`fixed`)은 클라이언트가 계산해서 보낸다(현재 4명 중 하나라도 `false`면
`true`를 보내고, 4명 다 `true`면 `false`를 보낸다).

## 클라이언트 (`components/team-builder/RosterBoard.tsx`)

- 기존 `selectedForSwap`/`handleSwapClick`(클릭 스왑) 로직을 제거한다.
- `Nameplate` 클릭 핸들러를 "그 entry의 `fixed`를 토글해 저장"으로 바꾼다.
  `selected` prop은 제거하고, 대신 `entry.fixed`를 받아 배지를 그린다.
- 02 표 전용 드래그 상태 추가(01의 `draggingId`/`dragOverTarget`과 이름
  충돌을 피하기 위해 별도 state) — 드래그 시작은 `fixed`가 아닌 카드만,
  드롭은 같은 티어 칼럼 + 대상이 `fixed`가 아닐 때만 스왑 API 호출.
- "고정" 칼럼: 각 팀 행 오른쪽에 토글 버튼, 클릭 시 `team-fix` API 호출 후
  응답으로 entries 갱신(또는 팀 API처럼 낙관적 업데이트 + 실패 시 되돌림).
- 표 셀 패딩을 줄인다(`px-3 py-2` → `px-2 py-1.5` 등, 실제 값은 구현 시 화면
  보고 조정).

## 테스트

- `PATCH .../[entryId]`가 `fixed`를 받아 저장하는지(수동 검증 — 기존 라우트도
  자동화 테스트 없음, 관례 유지).
- `team-fix` 라우트: 4명 전부 고정/해제되는지(수동 검증).
- `RosterBoard` 컴포넌트 테스트: 클릭하면 고정 API 호출, 고정된 카드는
  `draggable=false`, 고정된 칸으로의 드롭은 스왑 API를 호출하지 않음, "고정"
  칼럼 클릭 시 4명 전부에 대해 올바른 목표값으로 API 호출.
