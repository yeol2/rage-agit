# 리더보드/내전페이지 개편 (16매치 창·관리자 검색·등수 변화·01 종합점수)

## 배경

내전이 주 2회로 늘어나면서 기존 "최근 12매치(내전 3회)" 창이 실제 운영
빈도보다 좁아졌다. 이번 스펙은 서로 독립적인 4개 UI/데이터 변경을 한 번에
묶어 진행한다:

1. 랭킹 집계 창을 12매치→16매치로 넓힌다.
2. 관리자에게만 리더보드 검색 기능을 준다.
3. 내전(4매치) 세션이 끝날 때마다 등수 변화(상승/하락/신규)를 시각화한다.
4. team-builder "01 티어 테이블"에서 관리자에게만 각 네임플레이트에 최근
   16매치 종합점수를 보여준다.

## 범위

**포함**: 위 4개 항목 전부.

**제외**:
- 평균등수/평균킬 탭의 등수 변화 추적 — 종합점수 탭만 추적한다(사용자
  명시적 확인).
- 등수 변화 이력(과거 여러 세션의 변화 기록) — 직전 스냅샷 대비 현재만
  비교한다. 히스토리 뷰는 범위 밖.
- 검색 결과에서 시상대(top3) 필터링 — top3는 검색과 무관하게 항상 그대로
  보여준다.

## 1. 최근 12매치 → 16매치

- `lib/rankingStats.ts`: `MIN_GAMES_FOR_RANKING` 12 → 16. `RankingWindow`
  타입과 `fetchRankingStats`의 `'recent12'` 케이스를 `'recent16'`으로
  리네이밍(코드 전체에서 12/16 혼동 방지).
- 새 마이그레이션 `0021_recent_ranking_window_16.sql`: `member_recent_ranking_stats`
  뷰의 `where r.rn <= 12` → `<= 16` (0013과 같은 구조, `create or replace view`).
- `TierRankingPodium.tsx`의 `WINDOW_OPTIONS`, `WINDOW_HELP`, `AGGREGATION_RULES`
  문구를 "최근 16매치 / 최근 내전 4회"로 갱신. `Window` 타입도
  `'recent12'` → `'recent16'`로 맞춰 리네이밍.
- `app/dashboard/page.tsx`, 관련 테스트 파일(`TierRankingPodium.test.tsx`,
  `rankingStats.test.ts`)의 `recent12` 참조도 함께 리네이밍.

## 2. 관리자 검색창

- `TierRankingPodium.tsx`의 "4위 이하" 표 헤더(`등수/닉네임/티어/뱃지/점수`)
  바로 위에, `isAdmin`일 때만 오른쪽 정렬 검색 인풋을 추가한다.
- 상태: `const [searchQuery, setSearchQuery] = useState('')`. 닉네임
  부분일치(대소문자 무시)로 `restRanked`만 필터링해서 렌더한다 — 시상대
  top3(`top` 배열)는 검색과 무관하게 그대로 유지.
- 등수 번호(`index + 4`)는 필터링 **전** 전체 순위 기준을 유지해야 하므로,
  `restRanked.map((member, index) => ...)` 대신 먼저 `(member, originalIndex)`
  쌍을 만들고 그 다음에 검색어로 필터링하는 순서로 구현한다.
- 필터링 후 0명이면 표 대신 "검색 결과가 없습니다" 텍스트를 보여준다.
- 검색 인풋은 관리자 전용이므로 서버 데이터 자체는 안 바뀐다 — 순수
  클라이언트 필터.

## 3. 등수 변화 표시 (종합점수 전용)

### 데이터 모델

새 마이그레이션 `0022_ranking_snapshots.sql`:

```sql
create table ranking_snapshots (
  id uuid primary key default gen_random_uuid(),
  window text not null check (window in ('recent16', 'alltime')),
  group_id text not null,
  member_id uuid not null references members(id) on delete cascade,
  rank_position integer not null,
  captured_at timestamptz not null default now(),
  unique (window, group_id, member_id)
);

grant select on ranking_snapshots to anon;
grant select on ranking_snapshots to authenticated;
grant insert, update, delete on ranking_snapshots to authenticated;
```

- `group_id`는 `TIER_GROUPS`(`lib/dashboardData.ts`)의 `id` 값을 그대로
  쓴다(`'all'` + 티어 그룹 5개) — 지금 리더보드 탭 구조와 정확히 대응시켜서,
  어느 탭에서 보든 그 탭 기준 등수 변화가 나오게 한다.
- `unique (window, group_id, member_id)`라 캡처할 때마다 `upsert`로 이전 값을
  덮어쓴다 — 항상 "가장 최근 세션 이전" 스냅샷 하나만 유지.

`scrim_rosters`에 컬럼 추가(같은 마이그레이션):

```sql
alter table scrim_rosters add column if not exists ranking_snapshot_captured_at timestamptz;
```

- 이 로스터(내전 세션)에서 스냅샷을 이미 캡처했는지 표시하는 1회성 플래그.
  라운드 4개 도달 시 한 번만 캡처하고, 이후 폴링에서는 다시 안 건드린다.

### 캡처 트리거

새 라우트 `POST /api/ranking-snapshots/capture` (`{ rosterId }`):

1. `scrim_rosters.ranking_snapshot_captured_at`이 이미 채워져 있으면 즉시
   `{ captured: false, reason: 'already-captured' }` 반환(멱등).
2. `fetchRankingStats('recent16')`, `fetchRankingStats('alltime')`을 서버에서
   호출해(기존 함수 재사용) 두 윈도우 각각 `eligibleForRanking` → 그룹별로
   `topByRageScore`(그룹 전체 크기, `limit = groupRows.length`)로 순위를 낸다.
   그룹은 `'all'`(전체) + `TIER_GROUPS`의 티어별 그룹 5개.
3. 나온 `(window, group_id, member_id, rank_position)` 행 전체를
   `ranking_snapshots`에 `upsert`(충돌 시 `rank_position`/`captured_at` 갱신).
4. `scrim_rosters.ranking_snapshot_captured_at = now()`로 갱신.

호출 지점: `app/api/scrim-roster/round-sheet/poll/route.ts`가 폴링 후 이번
로스터의 라운드 수를 조회해(기존 `round-sheet` GET이 쓰는 것과 같은 방식)
**정확히 4개 라운드가 채워진 상태를 처음 확인했을 때** 위 캡처 라우트를
서버 내부에서 직접 호출한다(별도 HTTP 왕복 없이 같은 로직을 함수로 분리해
호출). 이미 `ranking_snapshot_captured_at`이 있으면 2단계에서 바로 멱등
반환되므로, 폴링이 여러 번 일어나도 안전하다.

### 화면 표시

- `TierRankingPodium.tsx`가 페이지 로드 시 `ranking_snapshots`을 조회해
  `(window, group_id) → Map<memberId, rankPosition>`을 만든다. `activeMetric
  === 'rageScore'`이고 `window`/`group`이 스냅샷에 있는 조합일 때만 화살표를
  계산한다(평균등수/평균킬 탭은 항상 표시 안 함).
- 각 행(시상대 top3 포함, 4위 이하 표 포함)의 현재 순위(`index + 1`)와
  스냅샷의 `rank_position`을 비교:
  - 스냅샷에 그 `member_id`가 없음 → 네온색 "NEW" 배지.
  - 현재 순위 숫자가 더 작음(올라감) → 빨간 ▲ + 상승폭(예: `▲2`).
  - 더 큼(내려감) → 파란 ▼ + 하락폭.
  - 같음 → 아무것도 안 보여줌.
- 배치: 각 등수 칸(시상대 카드 하단, 4위 이하 표의 각 행) 가장 오른쪽.
  4위 이하 표는 `RANKING_GRID`에 칸을 하나 추가하기보다, 기존 "점수" 칸
  안에서 점수 오른쪽에 작게 붙인다(그리드 열 재계산으로 인한 폭 어긋남을
  피하기 위함 — `RANKING_GRID`의 열별 폭 계산식이 `TierRankingPodium.tsx`
  상단 주석에 있는 대로 서로 얽혀 있어, 새 열을 추가하면 티어 열 중앙 정렬이
  깨진다).

## 4. 01 네임플레이트 종합점수 (관리자 전용)

- `RosterBoard.tsx`에서 `useAdmin()`이 true일 때만, 마운트 시
  `fetchRankingStats('recent16')` + `rageScores(rows, TIER_SCORE_BANDS,
  RAGE_SCORE_STEEPNESS)`를 호출해 `Map<memberId, score>`를 만든다.
- `TIER_SCORE_BANDS`(현재 `TierRankingPodium.tsx`에 있는 `TIER_BANDS`
  계산 로직)를 `lib/rankingStats.ts`로 옮겨 공용 상수로 export하고, 두
  컴포넌트가 같은 것을 import해서 쓴다(계산 기준 불일치 방지).
- `Nameplate`에 `score?: number` prop 추가. `entry.memberId`가 맵에 있고
  랭킹 자격(16경기 이상 등)을 만족할 때만 값이 온다 — 없으면 배지 자체를
  안 그린다.
- 배지 위치: 카드 감싼 `<div className="relative">` 안, **왼쪽 아래
  모서리**(`absolute bottom-0 left-0` 계열, 작은 텍스트) — VipCrown(오른쪽
  위)·X 삭제 버튼(오른쪽 중간)과 겹치지 않는 유일한 빈 모서리.
- 01 티어 칸에서만 쓴다(`fixed` prop처럼 02 표에는 안 넘긴다 — 02는 이미
  고정 배색 등으로 정보가 많아 새 배지를 더하지 않는다, 스펙 범위 밖).
