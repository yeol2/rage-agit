# 팀 구성 테이블 (1단계: 명단 긁기 + 티어 자동배치)

## 배경

내전 64명(4티어 × 16명)을 대기 음성채널에서 모은 뒤, 관리자가 수동으로 팀을 짠다.
이번 스펙은 그 준비 단계 — "누가 왔는지 긁어와서 티어별 칸에 기본으로 나눠 보여주는
화면"까지다. 실제 드래그로 팀 짜기, 티어 승격 조정, 라인/전체 리롤은 다음 스펙(2단계)
에서 다룬다.

## 범위

**포함**:
- 관리자가 홈페이지 새 페이지(`/team-builder`)에서 버튼을 눌러 디스코드 대기
  음성채널의 현재 접속자 목록을 일회성으로 긁어온다.
- 긁어온 사람을 `members.discord_username`으로 매칭한다.
- 매칭된 사람은 `members.tier` 기준으로 1~4티어 칸에 기본 배치한다
  (0~1.5→1티어, 2~2.5→2티어, 3~3.5→3티어, 4~5→4티어).
- 매칭 안 된 사람은 화면 하단에 "미매칭"으로 따로 보여준다.
- 결과를 DB에 저장해 페이지를 새로고침하거나 나중에 다시 열어도 유지된다.

**제외 (2단계로 미룸)**:
- 16명이 안 채워진 티어 칸을 상위 티어에서 끌어올리는 수동 조정 UI (드래그 앤 드롭)
- 팀(4인 스쿼드 단위) 구성 및 저장
- 라인 리롤 / 전체 리롤 버튼

## 아키텍처

```
[관리자] 홈페이지 /team-builder 진입
  → AccessGate(기존 6자리 암구호, components/members/AccessGate.tsx 재사용)로 잠금 해제
  → "명단 긁기" 버튼 클릭
     → POST /api/scrim-roster/fetch (서버 전용 API 라우트)
        → discord.js Client를 이 요청 동안만 생성해 로그인
        → 지정된 길드의 대기 음성채널(DISCORD_WAITING_VOICE_CHANNEL_ID) 접속자 조회
        → Client 즉시 destroy (상시 프로세스 아님)
     → 접속자의 discord global username을 members.discord_username과 매칭
     → 매칭 성공: member_id, tier, tier_slot(1~4 매핑) 채움
     → 매칭 실패: member_id/tier/tier_slot null, matched=false
     → scrim_rosters(신규 행) + scrim_roster_entries 로 DB에 저장
  → 화면이 최신 scrim_rosters 를 다시 조회해 4개 티어 칼럼 + 미매칭 목록 렌더
```

## DB 스키마 (`supabase/migrations/0016_scrim_roster.sql`)

```sql
create table if not exists scrim_rosters (
  id uuid primary key default gen_random_uuid(),
  clan_id uuid not null references clans(id),
  fetched_at timestamptz not null default now()
);

create table if not exists scrim_roster_entries (
  id uuid primary key default gen_random_uuid(),
  roster_id uuid not null references scrim_rosters(id) on delete cascade,
  discord_username text not null,        -- 음성채널에서 긁은 원본 global username
  member_id uuid references members(id), -- 매칭 성공 시만 채움
  tier numeric(3,1),                     -- 매칭 시점의 티어 스냅샷
  tier_slot int,                         -- 1~4, 매칭 성공 시 기본 매핑값
  matched boolean not null default false
);

alter table scrim_rosters enable row level security;
alter table scrim_roster_entries enable row level security;

create policy "scrim_rosters_select_public" on scrim_rosters for select using (true);
create policy "scrim_roster_entries_select_public" on scrim_roster_entries for select using (true);
```

- 새로 긁을 때마다 `scrim_rosters`에 새 행을 추가한다 (기존 행은 지우지 않고 히스토리로
  남긴다). 화면은 항상 `fetched_at` 최신 행 하나만 보여준다.
- INSERT/UPDATE는 공개 정책을 열지 않는다 — service role 키를 쓰는 서버 API 라우트에서만
  쓴다 (members 테이블과 동일한 패턴).

## 티어 매핑

```ts
function tierSlot(tier: number): 1 | 2 | 3 | 4 {
  if (tier <= 1.5) return 1;
  if (tier <= 2.5) return 2;
  if (tier <= 3.5) return 3;
  return 4; // 4, 4.5, 5
}
```

16명 초과/미달 상태 그대로 보여준다 (자동 보정 없음 — 2단계에서 사람이 손으로 조정).

## 화면 (`app/team-builder/page.tsx`, `components/team-builder/`)

- Nav에는 아직 추가하지 않는다 (URL을 아는 관리자만 접근). `siteConfig`에 항목을 넣지 않는다.
- 기존 `AccessGate` 재사용 — 같은 캐주얼 잠금(진짜 보안 아님, 클랜원 페이지와 동일 전제).
- 상단: "명단 긁기" 버튼, 마지막 갱신 시각(`scrim_rosters.fetched_at`).
- 1~4티어 4개 칼럼, 칼럼 헤더에 "n/16명" 카운트.
- 하단: "미매칭 (n)" 섹션 — `discord_username` 원본 텍스트만 나열.
- 로딩/에러 상태: 버튼 클릭 후 조회 중 스피너, 음성채널 접속자가 0명이거나 API 에러 시
  메시지 표시.

## 사전 준비 (관리자가 이번 세션에서 함께 진행)

디스코드 봇이 아직 없으므로 아래를 새로 만든다:

1. Discord Developer Portal에서 애플리케이션 생성 → Bot 추가 → 토큰 발급.
2. Bot에 `Server Members Intent`, `GUILD_VOICE_STATES` 관련 권한 활성화.
3. 봇을 대상 길드에 초대 (OAuth2 URL, `View Channels` + `Connect` 권한이면 충분 — 메시지
   권한 불필요).
4. `.env.local`에 추가:
   - `DISCORD_BOT_TOKEN`
   - `DISCORD_GUILD_ID`
   - `DISCORD_WAITING_VOICE_CHANNEL_ID`

## 테스트

- `tierSlot()` 순수 함수 유닛 테스트 (경계값: 1.5/2/2.5/3/3.5/4).
- 매칭 로직(디스코드 username 목록 + members 목록 → entries 배열) 유닛 테스트 —
  discord.js/Supabase 네트워크 호출과 분리해서 순수 함수로 뺀다 (`lib/memberStats.ts`
  패턴과 동일).
- API 라우트 자체는 실제 디스코드 봇 토큰이 있어야 통합 테스트가 가능하므로, 이번
  스펙에서는 수동 검증(브라우저로 실제 버튼 클릭)으로 대신한다.
