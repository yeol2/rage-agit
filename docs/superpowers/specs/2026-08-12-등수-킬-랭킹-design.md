# 클랜원 등수+킬 랭킹 (대시보드 포디움)

## 목적

대시보드의 `TierRankingPodium`은 지금 `lib/dashboardData.ts`의 목업 `score`로 채워져 있다.
이걸 실제 경기 데이터 기반 두 가지 지표로 교체한다.

- **우승확률**: 매치 팀등수에 점수를 매겨(1등 10 / 2등 6 / 3등 5 / 4등 4 / 5등 3 / 6등 2 /
  7~8등 1 / 9등 이하 0) 매치당 평균을 낸 뒤, 같은 비교 그룹(티어 탭) 안에서 그 평균이
  상대적으로 얼마나 높은지를 확률로 환산한 값. "다음 내전에서 우승할 확률"이라는 직관적 이름을
  붙였지만 실제로는 그룹 내 상대적 위치를 나타내는 추정치다.
- **평균킬**: 매치당 평균 킬수. 그룹 안에서 단순 정렬.

두 지표 모두 티어 탭(전체/0~1.5/2~2.5/3~3.5/4~) 별로 보고, 최근 10경기 / 역대 전체 두 창(window)을
토글로 전환할 수 있다.

이 스펙은 랭킹 계산 로직과 포디움 UI만 다룬다. 다음은 스코프 밖이며 별도 세션에서 진행한다:
- 디스코드 스크린샷으로 2025~2026년 전체 경기 백필
- 내전 기록 + 예정 일정 페이지 분리 (지금 대시보드에서 `RecentScrimsList`를 빼는 작업)

## 점수 규칙

팀등수 → 점수 변환 (상위 8팀만 점수, 9등 이하는 0점):

| 팀등수 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9+ |
|---|---|---|---|---|---|---|---|---|---|
| 점수 | 10 | 6 | 5 | 4 | 3 | 2 | 1 | 1 | 0 |

## 데이터 레이어

`supabase/migrations/0010_member_recent_stats.sql`의 `member_recent_stats` 뷰(최근 10경기 창)
패턴을 그대로 따른다.

**신규 마이그레이션 `0011_member_ranking_stats.sql`**:

1. `member_recent_stats`에 `avg_placement_points` 컬럼 추가 (위 점수표를 `case`로 구현한
   `avg(...)`, `team_rank`가 이미 컬럼으로 있으니 window 안에서 계산).
2. 신규 뷰 `member_alltime_stats` — `member_recent_stats`와 같은 컬럼 구성(`avg_kills`,
   `avg_placement_points` 포함)이지만 `row_number() over (...) <= 10` 제한이 없다. 여기의
   `game_count`가 클랜원의 **통산 경기 수**이며, 최근10 창을 볼 때도 자격 판정 기준으로
   이 값을 쓴다(최근10 뷰의 `game_count`는 최대 10으로 잘리므로 자격 판정에 못 쓴다).
3. 두 뷰 모두 `anon`/`authenticated`에 `select` grant (0010과 동일 패턴).

**최소 경기 자격**: 통산(`member_alltime_stats.game_count`) 12경기(내전 3회 × 4경기) 미만인
클랜원은 어느 지표·어느 창에서도 랭킹에서 제외한다.

## 계산 로직 — `lib/rankingStats.ts`

`lib/memberStats.ts`와 같은 패턴: Supabase 호출은 파일 뒷부분의 조회 함수에만 두고, 계산은
순수 함수로 분리해 네트워크 없이 단위테스트한다.

```ts
export const MIN_GAMES_FOR_RANKING = 12;

export interface RankingStatsRow {
  memberId: string;
  tier: number;
  totalGameCount: number;   // member_alltime_stats.game_count — 자격 판정용
  avgKills: number;         // 선택된 창(recent10 | alltime) 기준
  avgPlacementPoints: number; // 선택된 창 기준
}

// 자격 미달 인원을 제외한다.
export function eligibleForRanking(rows: RankingStatsRow[]): RankingStatsRow[];

// 평균킬 상위 N명 (그냥 정렬, 확률 변환 없음).
export function topByAvgKills(rows: RankingStatsRow[], limit = 3): RankingStatsRow[];

// z-score + softmax로 그룹 내 우승확률(%) 계산.
// 표준편차가 0이면(전원 동점) 균등 확률로 나눈다.
export function winProbabilities(
  rows: RankingStatsRow[],
  temperature: number,
): Array<RankingStatsRow & { probability: number }>;

export function topByWinProbability(
  rows: RankingStatsRow[],
  temperature: number,
  limit = 3,
): Array<RankingStatsRow & { probability: number }>;
```

`temperature`는 상수로 시작하되(예: `1.5`), dev 서버에서 실제 데이터를 넣고 "1등도 25% 안팎"이
되는지 눈으로 보면서 조정한다. 튜닝 후 값을 파일 상단 상수로 고정.

**조회 함수** (`lib/rankingStats.ts` 뒷부분):

```ts
export async function fetchRankingStats(
  window: 'recent10' | 'alltime',
): Promise<RankingStatsRow[]>;
```

`member_recent_stats`(recent10일 때) 또는 `member_alltime_stats`(alltime일 때)에서
`avg_kills`/`avg_placement_points`를 가져오고, 통산 `game_count` 자격 판정을 위해
`member_alltime_stats`를 항상 같이 조회해 `member_id`로 합친다(recent10을 볼 때도 자격은
통산 기준).

## UI — `TierRankingPodium` 확장

- 지표 토글: 우승확률 / 평균킬 (버튼, 기존 티어 탭과 같은 스타일)
- 창 토글: 최근10경기 / 역대전체
- 기존 티어 탭(`TIER_GROUPS`: 전체/0~1.5/2~2.5/3~3.5/4~) 그대로 재사용
- 포디움 카드: IGN + 선택된 지표값 (`"23.4%"` 또는 `"4.2킬"`)
- `lib/dashboardData.ts`의 `Member`/`score`/`getTopMembers` 목업은 제거하고 `RankingStatsRow`
  + `topByWinProbability`/`topByAvgKills`로 교체. `TIER_GROUPS` 상수는 그대로 유지.
