# 02 팀 구성 테이블 — 클릭 스왑 이동 + VIP 정렬

## 배경

`/team-builder`의 "02 팀 구성 테이블"은 01의 나열 순서 그대로 팀 번호를 배정해
채워지는 것까지 구현됐다(2026-08-19 팀-번호-배정 스펙). 이번 스펙은 그 결과를
관리자가 손으로 다듬을 수 있게 하는 것 — 같은 티어 칸 안에서만 두 사람의 팀
번호를 맞바꾸는 클릭 상호작용과, VIP가 자기 등수만큼 앞 번호 팀에 들어가도록
한 번에 정렬해주는 "VIP 정렬" 버튼이다.

펀딩자 1회성 뽑기권과 VIP 뽑기 드래프트는 이번 스코프에서 뺀다 — 사용자가 수동
스왑으로 대체하기로 했다. "고정(fix)" 토글은 완전히 독립된 다음 스펙으로 미룬다.

## 범위

**포함**:
- 02 표의 네임플레이트를 클릭하면 선택되고, 같은 티어 칼럼의 다른 칸을 클릭하면
  둘의 팀 번호가 서로 바뀐다(좌우/티어 간 이동은 안 됨).
- 스왑은 즉시 DB에 저장된다(01의 드래그 저장 패턴과 동일하게 낙관적 업데이트 +
  실패 시 되돌림).
- "VIP 정렬" 버튼 — 내전에 참가 중인 VIP를 등수 오름차순으로 1번팀부터 채워지게
  자동으로 스왑한다.
- 02 표를 왼쪽으로 붙이고 오른쪽에 세로 버튼 칼럼을 만든다("VIP 정렬"이 첫 버튼,
  나중에 리롤 버튼들이 여기 추가될 자리).

**제외**:
- 펀딩자 지정, VIP 뽑기 드래프트(수동 스왑으로 대체).
- 고정(fix) 토글(다음 스펙).
- 전체/티어별 리롤(고정 기능 이후).

## 상호작용

02 표의 네임플레이트를 클릭하면:
- 아무것도 선택 안 된 상태 → 그 칸이 선택됨(기존 `tierNameplateSelectedStyle`
  진한 배색으로 표시).
- 이미 선택된 칸을 다시 클릭 → 선택 해제.
- 같은 티어 칼럼의 다른 칸을 클릭 → 두 칸의 `team_number`를 맞바꾸고 선택 해제.
- 다른 티어 칼럼의 칸을 클릭 → 스왑 없이 새로 클릭한 칸으로 선택이 옮겨간다.
- 빈 칸(placeholder)은 클릭해도 아무 일도 안 일어난다.

## API

### `POST /api/scrim-roster/entries/swap`

`{ entryIdA: string, entryIdB: string }`

두 entry의 `team_number`를 서로 바꿔 저장한다. 개별 PATCH를 두 번 부르는 대신
한 번에 처리해, 하나만 저장되고 하나는 실패하는 상태를 피한다. 두 entry의
`tier_slot`이 다르면(클라이언트가 막고 있지만 방어적으로) 400을 돌려준다. 성공
시 두 entry(갱신된 `team_number` 포함)를 돌려준다.

### `POST /api/scrim-roster/vip-sort`

`{ rosterId: string }`

서버가 최신 entries를 다시 조회해, `vipRank`가 있는 entry만 골라 등수 오름차순
정렬한다. i번째(0-based) VIP를 (i+1)번팀의 **자기 티어 칼럼** 자리와 맞바꾼다 —
그 자리에 원래 있던 사람은 자동으로 그 VIP가 있던 팀 번호로 옮겨간다(스왑이므로
아무도 사라지지 않는다). 이미 정렬된 상태에서 다시 눌러도 스왑이 안 일어나는
멱등 동작이다. 참가 중인 VIP가 없으면(빈 배열) 아무것도 안 바꾸고 그대로
entries를 돌려준다(에러 아님). 참가 VIP 수가 팀 수(`targetPerTier`)보다 많은
경우는 현재 VIP가 최대 10명이고 실제 내전 팀 수는 항상 그보다 많아 실질적으로
발생하지 않는다 — 별도 처리를 두지 않는다.

## 클라이언트 (`components/team-builder/RosterBoard.tsx`)

- `Nameplate`에 `onClick?: () => void` prop을 추가한다(draggable=false일 때만
  쓰는 클릭 핸들러 — 01의 드래그 카드와는 별개).
- 새 상태 `selectedForSwap: string | null` (entry id).
- 02 표 렌더링에서 각 칸의 `onClick`을 연결: 선택 로직(위 상호작용 규칙)과 스왑
  API 호출, 낙관적 업데이트 + 실패 시 되돌림.
- "VIP 정렬" 버튼: 클릭 시 `/api/scrim-roster/vip-sort` 호출, 응답으로 entries
  갱신. 로딩 중 비활성화, 실패 시 에러 메시지.
- 레이아웃: 02 표를 감싸는 컨테이너를 `flex` 로 바꿔 표(왼쪽, 나머지 공간)와
  버튼 세로줄(오른쪽, 고정 너비)을 나란히 배치한다.

## 테스트

- 스왑 API: 두 entry의 `team_number`가 정확히 맞바뀌는지, `tier_slot`이 다르면
  400을 내는지(수동 검증 또는 있으면 유닛 테스트로).
- VIP 정렬 순수 로직(어떤 스왑이 필요한지 계산하는 부분)은 pure function으로
  빼서 유닛 테스트: VIP 여러 명 시나리오, 참가 VIP 없음, 이미 정렬된 상태(스왑
  없음).
- `RosterBoard` 컴포넌트 테스트: 클릭 → 클릭(같은 티어) → 스왑 API 호출 확인,
  클릭 → 다른 티어 클릭 → 스왑 없이 선택만 옮겨감, VIP 정렬 버튼 클릭 → API
  호출 + 결과 반영.
