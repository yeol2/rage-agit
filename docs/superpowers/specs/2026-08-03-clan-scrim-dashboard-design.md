# 클랜 내전 대시보드 (MVP) 설계 문서

## 배경 및 목적

배틀그라운드(PUBG) 클랜을 위한 서비스 사이트의 첫 번째 단계로, [clanduck.com](https://clanduck.com/)과 유사한 클랜 운영 플랫폼을 목표로 하되 전체 기능(클랜/연합 관리, 스크림 운영, 실시간 리더보드, 방송 송출, 랭킹, 디스코드 봇, 다중 플랫폼 지원 등)을 한 번에 만들지 않는다.

MVP 범위는 다음으로 한정한다:
- 우리 클랜(단일 클랜) 소속 클랜원들의 카카오 배틀그라운드 계정(IGN)을 등록
- 매주 일요일 진행되는 클랜 내전(커스텀 매치) 기록을 카카오 배틀그라운드 Open API로 자동 수집
- 클랜원별 최근 10경기 내전 기준 통계를 계산해 공개 대시보드로 제공

향후 여러 클랜이 각자 가입해 사용하는 멀티테넌트 구조로 확장 가능하도록 데이터 모델에 `clan_id`를 처음부터 포함하지만, 로그인/가입 플로우 등 멀티테넌트 전용 기능은 이번 범위에 포함하지 않는다.

## 스코프 결정 배경

clanduck.com 기능 분석 결과 다음 서브시스템으로 구성되어 있음을 확인했다:
1. 클랜·연합 통합 운영 (권한 체계, 가입 승인)
2. 스크림 및 참가팀 관리
3. 자동 매치 집계 (PUBG Match ID/옵저버 폴링)
4. 실시간 리더보드 (WebSocket)
5. 방송 송출 (OBS 오버레이)
6. 랭킹 시스템
7. 매치 타임라인/리플레이
8. 디스코드 봇 연동
9. 다중 플랫폼 지원 (카카오/스팀/PS/Xbox)

이 중 이번 MVP는 3(자동 매치 집계, 카카오 한정)과 6(랭킹/통계)의 축소판만 다룬다. 나머지는 향후 별도 스펙으로 순차 진행한다.

## 아키텍처

**스택**
- Frontend/Backend: Next.js, Vercel 배포
- DB & 백그라운드 작업: Supabase (Postgres + Edge Functions cron)
- 외부 연동: 카카오 배틀그라운드 Open API
- 도메인: 별도 구매 후 Vercel에 연결

**데이터 흐름**
1. 관리자가 `/admin` (비밀번호 보호)에서 클랜원의 카카오 IGN을 등록/삭제/비활성화한다.
2. Supabase Edge Function이 주기적으로(초기값: 매주 일요일 저녁 폴링, 필요 시 빈도 조정) 등록된 각 멤버의 최근 매치 목록을 PUBG API로 조회한다.
3. `matchType = custom`인 매치만 후보로 걸러 매치 상세(참가자별 킬/데미지/순위 등)를 조회하고 Supabase DB에 저장한다.
4. "우리 클랜 내전 판별 로직"(아래 참고)을 적용해 각 매치에 `is_clan_scrim` 플래그를 태깅한다.
5. `is_clan_scrim = true`인 매치 중 각 멤버의 최근 10경기를 기준으로 통계를 집계해 대시보드에 표시한다.

**DB 스키마 (초안 — 실제 API 응답 구조를 받아본 뒤 필드를 확정한다)**
- `clans` (id, name) — MVP에서는 1행만 존재하지만 향후 멀티클랜 확장 대비로 둔다.
- `members` (id, clan_id, ign, pubg_account_id, active)
- `matches` (id, pubg_match_id, played_at, map, is_clan_scrim, raw_meta)
- `match_participants` (match_id, member_id, kills, damage, assists, dbno, placement, survive_time)

스키마 확정은 이번 스펙의 구현 범위가 아니라, 실제 PUBG API 응답을 받아온 뒤 이어지는 작업 단계에서 정한다.

## 내전(우리 클랜 스크림) 자동 판별 로직

전제: 클랜 내전은 매주 일요일, 하루 4판 진행되며 참여 인원은 매번 다르다.

**판별 절차**
1. 등록된 클랜원들의 최근 매치 중 `matchType=custom`인 것만 후보로 추린다.
2. 후보 매치들을 시간 군집화한다: 같은 날, 짧은 시간 간격(예: 서로 4~5시간 이내)으로 열린 매치들을 하나의 "세션"으로 묶는다.
3. 각 후보 매치에서 등록된 클랜원 참가자 수가 임계치 이상(예: 3명 이상)이면 `is_clan_scrim = true`로 자동 태깅한다.
4. 자동 태깅 결과는 승인 절차 없이 그대로 대시보드에 반영한다. 관리자 페이지에서 개별 매치의 `is_clan_scrim`을 손으로 토글해 오탐만 사후 수정할 수 있게 한다.

임계치(참가 인원수, 시간 간격)는 고정값이 아니라 실제 API 응답과 운영 결과를 보면서 조정한다.

## 대시보드 UI

**공개 대시보드 (`/`, 로그인 불필요)**
- 클랜 전체 랭킹 리스트: 멤버별 최근 10경기 기준 종합 점수 순 정렬 카드/테이블
- 각 멤버 카드: 평균 킬/데미지/어시스트, 평균 순위, 생존율
- 카드 클릭 시 멤버 상세 페이지로 이동

**멤버 상세 페이지 (`/member/[id]`)**
- 최근 10경기 요약 지표: 평균 킬/데미지/어시스트, 평균 순위/생존율, 랭킹 점수
- 경기별 기록 목록 테이블 (날짜, 맵, 킬, 데미지, 순위 등)
- 최근 10경기 추이 그래프 (킬/데미지/순위 변화 라인 차트)

**랭킹 점수 계산 (초안)**
- 킬 점수와 순위 점수의 가중합으로 계산한다: `점수 = 킬 * a + 순위점수(등수가 높을수록 큰 값) * b`
- 정확한 가중치 `a`, `b`는 자리만 잡아두고 실제 데이터를 보면서 조정한다.

## 관리자 기능 (`/admin`)

- 클랜 공용 비밀번호 로그인 (개인 계정 없이 단순 세션/쿠키 기반)
- 클랜원 목록 관리: IGN 추가/삭제/비활성화
- 매치 목록에서 자동 판별된 `is_clan_scrim` 값을 토글해 오탐 수정
- 폴링 상태 및 마지막 갱신 시각 확인

## 향후 확장 (이번 스코프 아님)

- 여러 클랜이 각자 가입/운영하는 멀티테넌트 구조
- 스크림 참가팀 신청/슬롯 배정 관리
- 실시간 리더보드 (WebSocket)
- 방송 송출용 OBS 오버레이
- 디스코드 봇 연동
- 스팀/PS/Xbox 등 카카오 외 플랫폼 지원

## 알려진 리스크 / 미확정 사항

- PUBG API의 매치 이력 롤링 제공 범위, 분당 요청 제한 등 실제 제약은 API 연동 단계에서 확인 후 폴링 주기를 조정해야 한다.
- 내전 자동 판별 임계치(참가 인원수, 시간 간격)는 초기 운영 데이터를 보며 튜닝이 필요하다.
- 랭킹 점수 가중치는 임시값이며 확정되지 않았다.
