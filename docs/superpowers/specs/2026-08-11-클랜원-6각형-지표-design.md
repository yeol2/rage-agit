# 클랜원 6각형 지표 화면 — 설계

## 목표

클랜원 개인의 최근 전적을 6각형(레이더 차트)으로 보여주는 `/members` 기능을 만든다. 홈페이지 카피가 이미 이 기능을 예고하고 있다 — "최근 10경기 동안 얼마나 잘했는지, 킬·데미지·순위·생존율로 쪼개서 확인합니다" — 그리고 `siteConfig.nav`에 `/members`가 `ready: false`로 이미 자리를 잡아뒀다.

## 왜 지금 이게 가능한가

10세션·44경기 전부 클랜원 지표가 채워졌다(미확인 닉네임 0개). 6각형에 쓸 6축 — 딜량·킬·헤드샷·생존시간·어시·등수 — 이 dak.gg 출처 34경기를 포함해 전부 결측 없이 들어 있는 걸 확인했다.

## 접근 제어

### 이건 캐주얼 가림막이지 진짜 보안이 아니다

`matches`/`match_participants`/`members`는 애초에 **공개 대시보드**로 설계됐다(`0004` 마이그레이션: "별명은 원래부터 공개였고 대시보드가 써야 하므로 남긴다"). anon 키는 프론트에 박혀서 사실상 공개값이고, RLS 정책은 전부 `for select using (true)`, grant도 전부 `grant select` — 쓰기 권한은 어디에도 없다(service_role 키만 쓰기가 되고, 이건 서버 스크립트와 Edge Function 안에만 있다).

즉 화면에 암구호 모달을 얹어도 **Supabase 를 직접 두드리는 사람은 못 막는다.** 이건 "타 클랜원이 지나가다 보는 걸 막는" 캐주얼 가림막으로 합의했고, 데이터 자체를 잠그는 건(RLS 재설계) 지금 범위 밖이다.

### 구현

- `NEXT_PUBLIC_CLAN_PASSPHRASE` 환경변수 — 관리자가 `.env.local`에 직접 추가한다. `NEXT_PUBLIC_` 접두사가 필요한 이유: 브라우저에서 비교해야 하니 빌드 결과물에 값이 박힌다(가림막의 한계와 일치하는 선택이다)
- `/members` 최초 진입 시 블러 배경 + 중앙 모달. 문구: "Rage 클랜원을 인증하세요 / 알맞는 비밀번호를 입력해야 이용 할 수 있습니다"
- 맞으면 `localStorage`에 기록해 그 브라우저에서는 다시 안 물어본다. 새 방문마다 재확인하지 않는다(합의됨)
- 서버가 아니라 클라이언트 컴포넌트에서 비교한다 — 서버로 보낼 이유가 없다(어차피 값이 클라이언트에 있으므로)

## 페이지 구조

### `/members` — 명단

- 암구호 통과 후: 티어별로 묶인 이름 그리드 + 검색창(닉네임 검색)
- 티어 그룹은 `TierRankingPodium`이 이미 쓰는 `TIER_GROUPS`를 재사용하되 **5티어를 4~4.5 그룹에 합쳐 `4~5티어`로 확장한다.** 지금 `TIER_GROUPS`는 4~4.5까지만 있어 5티어 2명이 "전체" 탭에서만 보인다 — 6각형의 티어 내 백분위 계산에서도 표본 2명은 그 자체로 의미가 없으니 인접 그룹에 합친다
- 이름을 클릭하면 `/members/[memberId]`로 이동

### `/members/[memberId]` — 개인 6각형

- `memberId`는 `members.id`(UUID)를 그대로 쓴다. 닉네임을 슬러그로 쓰지 않는 이유: 실제 `discord_nickname`에 `/`, `(`, 이모지가 섞인 경우가 있다(예: `Ez_MIIX/Lil(95)`) — URL에 안전하게 못 넣는다
- 표본이 4경기(내전 하루치) 미만이면 6각형 대신 "아직 내전 기록이 없습니다" 안내만 보여준다. 6각형을 그렸는데 사실 1~2경기짜리 우연이었다는 착시를 막는다

## 데이터

### 집계 범위

- 그 사람이 뛴 **최근 10경기**(전체 매치 중, 세션 단위가 아니라 매치 단위로 최신 10개)
- 부계정이 여러 개일 수 있으므로 `member_id` 기준으로 계정을 합쳐서 집계한다(닉네임이나 개별 계정 ID 기준이 아니다) — 이게 바로 이번 미확인 닉네임 정리 작업이 있어야 했던 이유이기도 하다
- 최소 4경기 미만이면 6각형을 그리지 않는다(위 참고)

### 6축

| 축 | 계산 | 비고 |
|---|---|---|
| 화력 | 평균 `damage_dealt` | |
| 결정력 | 평균 `kills` | |
| 정확도 | `sum(headshot_kills) / sum(kills)` | 경기별 비율 평균이 아니라 **합계 대 합계**로 계산 — 킬이 0인 경기가 있어도 0으로 나누기 문제가 안 생긴다 |
| 생존력 | 평균 `time_survived` | |
| 팀 기여 | 평균 `assists` | |
| 성적 | 평균 `team_rank`, 역순(낮을수록 좋음 → 축에서는 높게) | |

`heals`/`boosts`/`revives`는 dak.gg 출처 경기에서 `NULL`이라 6축에 안 쓴다(이미 설계된 대로 `AVG`가 `NULL`을 건너뛰므로 API 출처와 섞여도 문제없다).

### 정규화 — 같은 티어 그룹 안에서 백분위

절대값을 그대로 그리면 딜량 400과 어시 1을 같은 축 길이에 놓을 수 없다. 그래서 각 축을 0~100 백분위로 바꾸는데, **비교 대상을 클랜 전체가 아니라 같은 티어 그룹으로 한정한다.**

이유: 이 클랜은 0티어가 최상위, 5티어로 갈수록 초심자다. 클랜 전체 기준으로 백분위를 매기면 0티어는 항상 꽉 찬 육각형, 4~5티어는 항상 쭈그러든 육각형만 보게 된다 — 실력 그룹 안에서의 상대적 위치가 아니라 그냥 "티어가 낮다"는 사실만 재확인시키는 화면이 된다. 같은 그룹 안에서 매기면 "내 그룹에서 나는 어디쯤인가"라는, 실제로 동기부여가 되는 질문에 답한다.

## 화면

- 참고 이미지의 육각 그리드 + 다각형 채우기 구도를 쓰되, 색은 사이트 accent 컬러(`#FF9233`, 주황)로 맞춘다
- 본인 도형 하나만 그린다. 클랜 평균이나 티어 평균을 겹쳐 보여주는 건 이번 범위에 넣지 않는다(다음 확장 후보로 남긴다)
- 라벨: 화력 · 결정력 · 정확도 · 생존력 · 팀기여 · 성적

## 범위 밖

- RLS 재설계를 통한 진짜 접근 제어
- 클랜/티어 평균을 겹쳐 보여주는 비교 뷰
- `/matches`, `/rankings` 등 다른 `준비 중` 네비게이션 항목

## 참고: 지금 프로젝트 상태
