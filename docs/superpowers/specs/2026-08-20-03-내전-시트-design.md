# 03 내전 시트

## 배경

01(티어 테이블)·02(팀 구성 테이블)까지 완성됐다. 이번 스펙은 그 다음 단계 —
02에서 짠 팀으로 실제 내전(4매치)을 치르면서, 매치가 끝날 때마다 각 팀의
누적 성적을 보여주는 "03 내전 시트"다. 02→03 전환에는 "내전 드가자~" 버튼을
쓴다(01→02의 "팀 구성"과 달리 아무 조건 없이 언제든 누를 수 있다).

시트의 정확한 모양은 사용자가 참고 이미지로 제공한 PUBG 내전 스코어시트
템플릿을 그대로 따른다: 왼쪽부터 순위(메달 아이콘)·팀번호·플레이어 4명,
이어서 좌측 고정 PLACE/KILL/TOTAL(누적 최종 기준), 그 뒤로 ROUND 1~4 각각
Rank/Score(등수 배치점수)/Kill/Total 서브컬럼. **각 ROUND의 "Total"은 그 라운드까지의 누적
합산**이다(ROUND2의 Total = 1~2라운드 합).

## 범위

**포함**:
- `scrim_rosters.stage` 컬럼 추가(`'01' | '02' | '03'`) — 01/02/03 표시 상태를
  새로고침해도 유지. 기존 `showTeamTable`의 `useState(false)` 초기화 버그도
  같이 고친다.
- 기존 주 2회 자동 폴링(pg_cron `poll-matches`) 제거.
- 03 시트의 "폴링" 버튼 — 기존 `runPolling()`(공유 폴링 로직, 재구현 없음)을
  즉석 호출해 최신 매치를 가져온다.
- 팀별 라운드 점수·누적 Total을 저장 없이 즉석 계산(팀 번호 매칭 →
  `placement_points()` 재사용).
- ROUND 1~4 컬럼 껍데기는 항상 다 렌더링(참고 이미지의 빈 템플릿과 동일) —
  아직 안 온 라운드는 Rank/Score/Kill/Total 모두 "-"로 비워두고, 폴링될 때마다 그
  라운드 칸만 채워진다.
- 팀 순위(왼쪽 PLACE)는 매 라운드 갱신마다 누적 Total 기준으로 재정렬,
  상위 3팀 메달.

**제외**:
- 팀 킬합계/순위 수동 수정 기능 — 실제 폴링 오류 사례가 없어 이번 범위에서
  뺀다(YAGNI). 필요해지면 별도 스펙.
- 참가자 식별(미등록/부계정/개명) 문제 해결 — 기존 참가자 정리 절차가 담당,
  03은 그 결과를 그대로 씀.
- 매치별 상세 통계(데미지·어시·헤드샷 등) — 시트에 필요한 Rank·Kill만 쓴다.

## 데이터 모델 변경

### `scrim_rosters.stage`

```sql
alter table scrim_rosters add column if not exists stage text not null default '01'
  check (stage in ('01', '02', '03'));
```

- "팀 구성" 버튼 클릭 시 기존 `POST /api/scrim-roster/team-assignments`
  라우트가 `team_number` 갱신과 **같은 트랜잭션에서** `stage`도 `'02'`로
  같이 써준다(별도 API 호출 없음 — 이미 그 라우트가 team_number를 전부
  갱신하는 김에 한 컬럼 더 쓰는 것뿐).
- "내전 드가자~" 버튼 클릭 시에는 다른 부수 작업이 없으니, 아래 새 전용
  라우트 `PATCH /api/scrim-roster/[rosterId]/stage`를 호출해 `'03'`으로
  갱신한다.
- 01/02/03은 되돌아가지 않는 단방향 진행(기존 `showTeamTable` 코멘트와 동일한
  전제 — 한 번 넘어가면 앞 단계로 안 되돌림).
- 클라이언트는 `roster.stage`를 그대로 읽어 어느 섹션까지 보여줄지 결정한다
  (`stage >= '02'`면 02도 표시, `stage === '03'`이면 03도 표시 — 문자열
  비교로 충분하다).

### 자동 폴링 제거

```sql
select cron.unschedule('poll-matches');
```

`scripts/setup-cron.mjs`가 만든 예약을 없앤다. `polling_runs.trigger`의
`'cron'` 값은 과거 기록이니 스키마는 안 건드린다. `scripts/poll-matches.mjs`,
`supabase/functions/_shared/polling.mjs`(`runPolling()`)는 그대로 남겨
03의 "폴링" 버튼이 재사용한다.

## 점수 계산

라운드(매치) 하나의 팀 점수:

1. 그 매치의 `match_participants`에서, `member_id`가 이 로스터의
   `scrim_roster_entries.member_id`와 일치하는 행만 가져온다.
2. `scrim_roster_entries.team_number`로 그룹핑한다.
3. 팀킬 = 그룹 내 `kills` 합.
4. 팀순위 = 그룹 내 `team_rank`(실제 게임에서 팀원끼리 공유하는 값 — 여러
   값이 섞여 있으면 방어적으로 최솟값을 쓴다).
5. 그 라운드 팀 점수 = 팀킬 + `placement_points(team_rank)`(기존 SQL 함수
   그대로 재사용, 새로 안 만듦).

N라운드까지의 누적 Total = 1~N라운드 팀 점수의 합.

로스터 멤버 중 그 매치에서 못 찾은 사람은 기여분 0. 팀에 매칭된 인원이
하나도 없으면 그 팀 그 라운드는 Rank/Score/Kill 모두 "-"로 표시(누적
계산에서는 0으로 취급).

**순위/재정렬**: 화면에 그려지는 팀 행 순서는 항상 "지금까지 기록된
라운드까지의 누적 Total" 내림차순이다. 라운드가 하나 추가돼 재조회될
때마다(폴링 성공 시) 전체를 다시 정렬한다. 왼쪽 PLACE 칼럼은 그 정렬
순서(1~16)이고, 1~3위는 메달 아이콘.

## API

### `PATCH /api/scrim-roster/[rosterId]/stage`

`{ stage: '03' }` — "내전 드가자~" 버튼 전용("팀 구성"→`'02'` 전환은 위처럼
`team-assignments` 라우트가 대신 처리하므로 이 라우트로는 안 옴). 현재
`stage`가 `'02'`가 아니면(아직 팀 구성 전이거나 이미 `'03'`이면) 400.

### `GET /api/scrim-roster/round-sheet?rosterId=...`

- 오늘 날짜(한국시간)로 `scrim_sessions`를 찾는다(없으면 라운드 0개로 응답).
- 그 세션의 `matches`를 `played_at` 오름차순으로 최대 4개까지 가져온다 —
  몇 번째로 나온 매치인지가 곧 라운드 번호(1~N)다.
- 각 라운드·각 팀(1~16)에 대해 위 "점수 계산" 로직을 적용해 Rank/Score(배치
  점수)/Kill/그 라운드까지의 누적 Total을 계산한다.
- 팀별 최종(가장 최근 라운드까지의) 누적 Total 기준으로 정렬한 배열을
  반환한다(각 팀 행에 순위·팀번호·플레이어 4명 닉네임도 포함).

### `POST /api/scrim-roster/round-sheet/poll`

- `runPolling({ supabase, apiKey, sinceHours: 3, ... })`을 호출한다(짧은
  시간창 — 방금 끝난 매치 하나를 잡는 용도).
- 새로 잡힌 스크림 매치가 없으면 `{ found: false }`를 반환(에러 아님).
- 있으면 `{ found: true }`를 반환 — 클라이언트가 이어서 `GET round-sheet`를
  다시 불러 화면을 갱신한다.

## 컴포넌트 / UI

- **"내전 드가자~" 버튼**: `components/team-builder/RosterBoard.tsx`의 02
  버튼 세로줄에 추가(VIP 정렬/리롤 버튼들과 같은 자리, 조건 없이 항상
  활성화). 클릭 시 `PATCH .../stage`(`{ stage: '03' }`) 호출 → 성공하면
  `stage` 상태 갱신해 03 섹션을 보여준다.
- **새 컴포넌트 `components/team-builder/RoundSheet.tsx`**: `stage === '03'`
  일 때 02 섹션 아래에 렌더링. 참고 이미지와 같은 표 레이아웃 —
  - 왼쪽부터: 순위(메달, 재정렬됨) · 팀번호(#01~16) · 플레이어 4명(닉네임
    4개를 "/"로 이어붙인 한 줄) · PLACE/KILL/TOTAL(누적 최종) ·
    ROUND 1~4(항상 다 보임) 각각 Rank/Score/Kill/Total. 숫자 칸은 40px 정사각형, 전체 중앙 정렬, 폴링 버튼은 표 아래 오른쪽.
  - "폴링" 버튼(표 아래 오른쪽) — 클릭 시 `POST round-sheet/poll` → 성공하고
    `found: true`면 `GET round-sheet` 재조회, `found: false`면 "아직 새
    경기가 없습니다" 메시지.
  - 마운트 시 `GET round-sheet`로 초기 데이터를 불러온다.

## 에러 처리

- `GET round-sheet`가 실패하면 에러 메시지 표시, 이전 데이터 유지(빈 화면
  대신).
- 폴링 API가 실패하면(PUBG API 오류 등) 에러 메시지, 재시도는 관리자가 다시
  버튼을 눌러서.
- 오늘 날짜 `scrim_sessions`가 아직 없을 때(폴링을 한 번도 안 돌렸을 때) 03
  섹션은 "아직 기록된 경기가 없습니다"로 라운드 0개 상태를 보여준다(에러
  아님).

## 테스트

- 순수 함수 `computeRoundScores`(위치: `lib/scrimRoster.ts` 또는 새
  `lib/roundSheet.ts`) 유닛 테스트: 팀킬 합산, `team_rank` 불일치 시 방어적
  처리, 누적 Total 계산, 매칭 안 된 팀 "-"처리, 정렬 순서·메달.
- `RoundSheet` 컴포넌트 테스트: ROUND 1~4 껍데기가 항상 다 보이는지(아직 안
  온 라운드는 "-"), 폴링 버튼 클릭 → API 호출 → 성공/실패(새 경기 없음)
  케이스, 재정렬 후 메달이 올바른 팀에 붙는지.
- `stage` 전환 컴포넌트 테스트: "팀 구성"/"내전 드가자~" 클릭 시 각각의
  PATCH 호출과 새로고침 시나리오(마운트 시 `roster.stage`로 섹션 노출 여부
  결정)를 검증.
