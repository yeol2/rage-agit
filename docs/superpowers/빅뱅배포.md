# 빅뱅배포 — 초기 배포 범위

> 이 문서는 "한 번에 배포할 초기 버전(빅뱅배포)의 크기를 어디까지로 잡았는가"를 기록한다. 세션별 상세 내용은 [sessions/](sessions/)의 각 폴더를 본다.

## 전체 그림

RageClan은 배틀그라운드 클랜을 위한 서비스다. 최종적으로는:

- 백엔드/배포: Supabase + Vercel
- 데이터 소스: 카카오 배틀그라운드 Open API (클랜 내전 자동 집계)
- 도메인: 별도 구매해 연결

이 전체 그림 중에서 **"빅뱅배포"로 부르는 초기 버전은 API 연동도, 실제 배포도 포함하지 않는다.** 아래 두 가지만 먼저 완성해 화면을 눈으로 확인 가능한 상태로 만드는 것이 목표였다.

## 초기 배포에 포함된 것

| 세션 | 내용 | 문서 |
|---|---|---|
| 랜딩페이지 | `/` — 클랜 소개 + 대시보드 진입 CTA | [sessions/2026-08-07-랜딩페이지/](sessions/2026-08-07-랜딩페이지/) |
| 대시보드 | `/dashboard` — 티어별 랭킹 포디움 + 최근 내전 목록 | [sessions/2026-08-08-대시보드/](sessions/2026-08-08-대시보드/) |

두 화면 모두 **목업 데이터**로 채워져 있다. 실제 카카오 API 응답이 아니라, 나중에 API 연동 시 그대로 갈아끼울 수 있도록 실제 데이터와 동일한 타입(`Member`, `ScrimSession` 등)으로 만든 가짜 값이다.

## 초기 배포에 포함되지 않은 것

- 카카오 배틀그라운드 API 연동, 실제 매치 수집/저장
- Supabase 연결, Vercel 실배포, 도메인 연결
- 로그인 (애초에 이번 범위에서는 필요 없음 — 공개 페이지)
- 클랜원 개인별 상세 페이지 (`/member/[id]`)
- 관리자 페이지 (클랜원 티어 지정, 내전 다시보기 URL 입력 등)
- 상단 네비게이션의 `MEMBERS`/`MATCHES`/`RANKINGS` (아직 페이지 없음, 비활성 상태로 표시만 해둠)

## 지금 상태 (이 문서 기준 시점)

- `master` 브랜치 하나에 랜딩페이지 + 대시보드가 모두 병합돼 있다.
- 테스트 24개, `npm run build` 통과.
- 실제 배포는 아직 하지 않았다 — 로컬에서 `npm run dev`로만 확인 가능하다.

## 브랜치 워크플로우

두 세션 모두 "브랜치를 따서 작업 → 리뷰 → master에 병합 → 브랜치 삭제" 패턴을 따랐다. 지금은 브랜치가 다 지워져 있지만, 실제 흐름은 다음과 같았다:

```
master ──●──────────────●──────────────●──────────────●──────●──▶
       dddcacc        0bf1aec        ddfab4e        4b6563f  6ac7783
       MVP 스펙        랜딩 병합       대시보드 스펙    대시보드 병합  how-docs
       (08-03)         (08-07)         (08-08)         (08-08)   (지금)
          \                ↗              \                ↗
           feature/landing-page            feature/dashboard
           → worktree-landing-page          → worktree-dashboard
             (SDD 1차 시도, 도중 폐기)         (SDD, Task 1~6)
           → 직접 구현으로 재시작              → 최종 리뷰 5건 수정
           → 다듬기 6라운드
```

랜딩페이지는 한 번 서브에이전트 방식(SDD)으로 절반쯤 만들다가 사용자가 "너무 오래 걸린다"며 전체를 취소하고, 직접 구현으로 다시 시작했다 — 그래서 `feature/landing-page` 안에 "폐기된 시도"가 끼어 있다. 대시보드는 처음부터 끝까지 SDD로 진행했고, 최종 리뷰에서 나온 지적 5건을 수정한 뒤 병합했다. 각 갈래의 자세한 내용은 세션별 `*.how.md`에 있다.
