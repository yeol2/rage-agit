# How: 내전 세션 묶기와 상세 보기

설계와 근거는 [설계 문서](../../specs/2026-08-10-내전-세션과-상세보기-design.md), 실행 계획은 [구현 계획](../../plans/2026-08-10-내전-세션과-상세보기.md)을 본다. 이 문서는 실제로 해보니 무엇이 달랐는가를 적는다.

## 3단계와 화면을 왜 같이 했는가

원래 3단계는 "같은 날 매치를 하나의 내전으로 묶기"였다. 그런데 묶기만 하고 보여주지 않으면 제대로 묶였는지 알 수 없다. 관리자가 원한 화면 — 내전 칸을 펼치면 매치 1~4, 또 펼치면 선수별 지표 — 에서 "내전 칸"이 곧 세션이므로 둘은 분리할 수 없었다.

대신 티어 랭킹 포디움은 목업으로 남겼다. 거기 필요한 `score` 를 무엇으로 계산할지는 아직 정한 바가 없고, 그건 그 자체로 설계가 필요한 주제다.

## 경기 수를 저장하지 않은 것이 옳았다

`match_count` 와 `participant_count` 를 컬럼에 저장하지 않고 뷰로 유도했다. 근거는 이미 겪은 일이었다 — 08-09 첫 수집에서 3경기만 잡혔고, 마지막 경기(12:38 시작)는 그때 아직 끝나지 않아 API 에 없었다. 나중 실행에서 4번째가 붙었다.

저장해뒀다면 그때마다 다시 세야 했고, 한 번 빠뜨리면 조용히 틀린 값이 남았을 것이다.

## 이동거리는 컬럼이 없었다

화면에 딜량·DBNO 옆에 이동거리를 넣기로 했는데, 막상 보니 `match_participants` 에 그 컬럼이 없었다. `raw_stats` 안에만 있고 그건 `0005` 에서 공개 읽기를 일부러 막아둔 컬럼이다.

dak.gg 의 "이동 거리" 가 무엇의 합인지 실측으로 확인했다 — `Ez_Grim` 의 07-26 경기에서 `walkDistance 1539.6 + rideDistance 4932.3 = 6472m` 이고 dak.gg 는 `6.47km` 로 보여준다. 두 값을 컬럼으로 빼고 `raw_stats` 에서 648행을 소급해 채웠다. 다시 가져올 필요가 없었다.

## 테스트가 통과했는데 화면이 안 떴다

가장 큰 실수였다. `ScrimSessionRow` 가 조회 함수를 프롭으로 받게 설계했다 — 테스트에서 네트워크 없이 확인하려고. 테스트 89개가 전부 통과했다.

그런데 브라우저에서 열자 화면이 비어 있었다:

```
Functions cannot be passed directly to Client Components
```

서버 컴포넌트(`RecentScrimsList`)가 클라이언트 컴포넌트(`ScrimSessionRow`)에 함수를 넘기고 있었다. React Server Components 는 함수를 경계 너머로 직렬화하지 못한다. **vitest 는 모든 것을 클라이언트로 렌더링하므로 이 경계가 존재하지 않았고, 그래서 테스트가 잡지 못했다.**

고친 방법은 프롭을 선택적으로 만들고 기본값을 임포트한 함수로 둔 것이다. 서버는 아무것도 넘기지 않고, 컴포넌트가 브라우저에서 직접 가져온다. 테스트는 여전히 가짜를 끼울 수 있다.

**교훈: 서버/클라이언트 경계는 브라우저에서 열어보기 전에는 검증되지 않는다.** 계획에 "실제 화면에서 확인" 단계를 넣어두지 않았다면 이 상태로 넘어갔을 것이다.

## 빌드가 잡은 것 두 가지

테스트는 타입을 검사하지 않는다. `npm run build` 가 두 가지를 잡았다.

**조인 결과의 타입.** `members(discord_nickname)` 조인을 Supabase 타입 추론이 확정하지 못해 `GenericStringError` 와의 합집합으로 잡혔다. `.returns<ParticipantRow[]>()` 로 모양을 명시했다.

**Deno 함수를 Next 가 타입 검사하려 했다.** `supabase/functions/poll-matches/index.ts` 가 `jsr:@supabase/supabase-js@2` 를 임포트하는데 Next 빌드가 그 모듈을 못 찾는다. 이건 폴링 자동화 세션에서 함수를 추가한 뒤 빌드를 안 돌려 잠복해 있던 문제다. `tsconfig.json` 의 `exclude` 에 `supabase/functions` 를 넣어 해결했다.

**앞으로 화면을 건드리는 세션에서는 `npm run build` 를 검증에 포함해야 한다.** 테스트만으로는 타입이 확인되지 않는다.

## 화면이 스크린샷과 일치했다

08-02 마지막 경기(한국시간 21:39)를 펼쳐 1등 팀을 확인했다:

| | 게임 결과 스크린샷 | 화면 |
|---|---|---|
| 1등 팀 | 팀 13 | 팀 13 |
| `Ez_Gi-Man` | 5킬 | 5킬 |
| `Ez_SoluTion` | 4킬 | 4킬 |
| `Ez_Buddy` | 3킬 | 3킬 |
| `Ez_tktktk` | 2킬 | 2킬 |

자동 검사는 전부 API 응답을 API 응답으로 검산하는 것이라, 응답 구조를 잘못 해석했더라도 통과한다. 화면까지 값이 제대로 흘러왔는지 확인할 수 있는 지점은 여기뿐이다.

`Ez_HxxJxx` 가 별명 없이 IGN 만 보이는 것도 확인했다 — 명단에 없는 사람이 화면에서도 눈에 띈다.

07-26 이 2경기인 것은 폴링을 만들기 전에 나머지가 API 목록에서 사라졌기 때문이다. 관리자가 dak.gg 스크린샷으로 채우기로 했고 그건 과거 내전 입력 세션에서 다룬다.

## 다음에 할 일
