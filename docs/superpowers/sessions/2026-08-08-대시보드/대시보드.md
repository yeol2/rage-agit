# 대시보드

> [빅뱅배포.md](../../빅뱅배포.md)의 초기 배포 범위 중 하나. 실제 구현 상태 기준으로 작성했다.

## 목적

`/dashboard` — 클랜 내전 결과를 한눈에 보는 화면. 로그인 없음. 랜딩페이지의 CTA가 실제로 이동하는 곳이다.

## 범위

이번 배포에 포함된 것: 티어별 랭킹 포디움 + 최근 내전 목록, 전부 목업 데이터.
포함되지 않은 것: 카카오 API 연동, 클랜원 개인별 상세 페이지, 관리자 페이지(티어 지정·다시보기 URL 입력).

## 데이터 (`lib/dashboardData.ts`)

```ts
interface Member { id: string; ign: string; tier: number; score: number }
interface ScrimSession { id: string; title: string; date: string; participantCount: number; matchCount: number; replayUrl: string | null }
interface TierGroup { id: string; label: string; tiers: number[] | null }
```

- `TIER_GROUPS`: 5개 고정 — `전체`(모든 티어) / `0~1.5티어` / `2~2.5티어` / `3~3.5티어` / `4~4.5티어`. 티어는 관리자가 수동 지정한다는 전제(이번 범위에 관리자 UI는 없음).
- `MEMBERS`: 17명의 목업. `4~4.5티어` 그룹에는 **의도적으로 1명만** 있다 — 포디움이 3명을 못 채웠을 때 어떻게 보이는지 실제로 검증하기 위한 픽스처다.
- `SCRIM_SESSIONS`: 10개, 최신순. 참여인원은 보통 64명(예외 2건: 60명), 경기 수는 보통 4경기(예외 1건: 3경기) — 실제 값이 그대로 표시되지, 고정 텍스트가 아니다.
- `getTopMembers(members, group, limit=3)`: 그룹의 `tiers`로 필터링(`null`이면 전체) 후 점수 내림차순 정렬, 상위 `limit`개 반환.
- `getRecentScrims(sessions, limit=10)`: 날짜 내림차순 정렬 후 상위 `limit`개 반환.
- `formatScrimDate(dateISO)`: `"2026-08-02 (일)"` 형태로 반환. 로컬 타임존이 아니라 `Date.UTC`로 직접 파싱한다(아래 how.md에 이유).

`score`의 가중치(킬점수+순위점수 가중합)는 처음부터 미확정 사항으로 남겨뒀다 — 목업은 그럴듯한 임의 값이다.

## 화면 구성

`app/dashboard/page.tsx` = `<Nav /> <h1 className="sr-only">대시보드</h1> <TierRankingPodium /> <RecentScrimsList /> <Footer />`

**TierRankingPodium** (`components/dashboard/TierRankingPodium.tsx`, `'use client'`)
- 티어 그룹 탭 5개 (`role="tab"`, 선택 시 `aria-selected`)
- 선택된 그룹의 Top3를 시상대 형태로 — 1위 가운데(가장 큼) · 2위 왼쪽 · 3위 오른쪽
- `전체` 탭에서만 각 카드에 티어 배지 표시
- 자리가 안 채워지면 순위 배지를 흐리게(`text-accent/30`) 하고 카드 안에 "—" 표시
- `members` prop을 받을 수 있고 기본값은 `MEMBERS` — 테스트에서 다른 데이터를 주입할 수 있다.

**RecentScrimsList** (`components/dashboard/RecentScrimsList.tsx`, 서버 컴포넌트)
- 최근 10개, 각 행: 내전 이름 · 날짜(요일) · 참여인원 · 경기수 · 다시보기(URL 있으면 버튼, 없으면 "다시보기 준비중" 비활성)
- `sessions` prop을 받을 수 있고 기본값은 `SCRIM_SESSIONS`

두 컴포넌트의 문구(아이브로우, 제목, 접미사 등)는 `siteConfig.dashboard`에서 가져온다 — 랜딩페이지와 동일하게 카피와 컴포넌트를 분리하는 원칙을 지켰다.

## Nav/Footer 변경

`siteConfig.nav`의 `DASHBOARD`, `siteConfig.footer.links`의 `대시보드` 항목을 `ready: true`로 바꿔서 실제 `Link`가 되도록 했다. 나머지(`MEMBERS`/`MATCHES`/`RANKINGS`, `클랜원`/`매치 기록`/`랭킹`)는 계속 비활성이다.
