# 디스코드 스크린샷 내전 읽기 절차

PUBG API 는 14일, dak.gg 는 약 2개월치만 준다. 그보다 오래된 내전
(2026-02 ~ 05) 은 디스코드에 올라온 결과 스크린샷밖에 남아 있지 않다.

## 이미지가 어떻게 생겼나

하루치가 **8장 연속**으로 들어 있고, 번호가 큰 쪽이 과거다 (역시간순).
한 매치마다 두 장이 짝을 이룬다.

| 종류 | 무엇이 있나 |
|---|---|
| 종합 시트 | 좌상단 날짜(`5. 10`), 16팀 × 로스터 4명, 라운드별 `[순위, 점수, 킬, 합계]` |
| 인게임 매치 결과 | `#1 팀 3` 형태의 팀 등수, 팀 총킬, **선수별 킬** |

한 블록은 `[시트, 인게임, 시트, 인게임, ...]` 순서고 **블록의 첫 시트가
그날 전체(모든 라운드)를 담은 최종본**이다. 시트는 누적이라 앞쪽 시트는
채워진 라운드가 더 적다 — 최종본 하나만 읽으면 된다.

### 시트의 라운드 칸 읽는 법

`ROUND 1` 아래 숫자 네 개는 `[순위, 점수, 킬, 합계]` 다.
점수는 순위에서 나온다 (1등 10 / 2등 6 / 3등 5 / 4등 4 / 5등 3 / 6등 2 /
7~8등 1 / 9등 이하 0). `점수 + 킬 = 합계` 인지 보면 잘못 읽은 줄이 걸린다.

### 인게임에서 잘린 선수

아래쪽 팀은 4번째 선수가 화면 밖으로 잘려 있는 일이 잦다.
그 선수의 킬은 **팀 총킬 − 보이는 선수들의 킬 합**으로 구하고,
닉네임은 시트의 그 팀 로스터에서 가져온다.

### 건너뛸 것

여러 클랜이 함께 한 **클랜 대항전**은 넣지 않는다. RAGE 인원이 절반도
안 되는 것으로 바로 구분된다.

이미 `matches` 에 들어 있는 날(2026-06 ~ 08) 도 넣지 않는다. 임포터가
자동으로 건너뛰지만, 애초에 전사하느라 시간 쓸 이유가 없다.

## 닉네임 맞추기

DB 의 계정은 전부 `Ez_` 접두사를 쓴다.

- 인게임: `[RAGE] Ez_chlrh` → `[RAGE] ` 를 뗀 `Ez_chlrh`
- 시트: `chlrh` → `Ez_` 를 붙인 `Ez_chlrh`

JSON 에는 **`Ez_` 가 붙은 형태**로 적는다.

## JSON 형식

`data/screenshot-scrims/YYYY-MM-DD.json`:

```json
{
  "scrimDate": "2026-05-10",
  "sheetFile": "126_1_1_Screenshot_2026-05-10_at_22.22.38.JPG.XHCUarRMO0.jpg",
  "sheet": [
    {
      "teamNo": 12,
      "rounds": [
        { "round": 1, "place": 13, "kills": 4 },
        { "round": 2, "place": 1, "kills": 7 }
      ]
    }
  ],
  "matches": [
    {
      "round": 1,
      "sourceFile": "133_1_1_Screenshot_2026-05-10_at_20.35.46.JPG.b9i6N2_rzZ.jpg",
      "teams": [
        {
          "teamNo": 12,
          "place": 13,
          "players": [
            { "ign": "Ez_DR01", "kills": 2 },
            { "ign": "Ez_vvvv", "kills": 1 },
            { "ign": "Ez_Woo", "kills": 1 },
            { "ign": "Ez_Rael2", "kills": 0 }
          ]
        }
      ]
    }
  ]
}
```

`sheet` 의 `place`/`kills` 는 시트에서, `matches` 의 선수별 킬은 인게임에서 읽는다.
**둘 다 적어야 한다** — 임포터가 대조해서 안 맞으면 넣기를 거부한다.

## 절차

1. 블록의 첫 시트를 읽어 날짜와 라운드 수를 확인한다.
2. 시트에서 16팀 × 라운드별 `[순위, 킬]` 을 옮긴다.
3. 인게임 이미지 4장에서 팀별 선수 킬을 옮긴다.
4. `node scripts/import-screenshot-scrims.mjs --dry-run data/screenshot-scrims/YYYY-MM-DD.json`
   - 형식 오류와 시트-인게임 불일치가 여기서 다 드러난다. **DB 에 접속하지 않는다.**
5. 통과하면 `--dry-run` 없이 다시 돌려 적재한다.
6. 미확인 닉네임이 나오면 `reference-participant-reconciliation` 절차를 따른다.

## 왜 시트와 인게임을 둘 다 적나

사람(이나 에이전트)이 눈으로 옮긴 숫자는 틀린다. 시트의 팀 킬 합계와
인게임 선수 킬의 합이 어긋나면 그 자리에서 잡히지만, 대조 없이 넣으면
틀린 값이 조용히 랭킹에 남는다. 전사량이 두 배가 아니라 — 시트는 팀당
숫자 두 개뿐이고, 그게 64명분 킬을 지켜준다.
